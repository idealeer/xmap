大规模网络扫描可能会引发一些伦理问题，因为它可能会无意中影响系统，并为网络运营商增加额外的工作。为了解决这些问题，XMap 开发团队遵循网络测量研究的伦理惯例。这些惯例确保我们的扫描活动是负责任的，并且对更广泛的互联网生态系统的影响最小。

## 我们的行动

为了确保符合伦理惯例，我们的行动如下：

1. **表明意图**：我们在源探测 IPv6 地址上设置网页，表明网络扫描的良性意图，并显示我们的联系方式。这使得网络运营商能够理解我们扫描的目的，并在必要时与我们取得联系。

2. **最小化影响**：我们限制探测速率并减轻探测强度，以最小化对被扫描网络的负面影响。这确保我们的扫描不会压垮目标系统或造成不必要的干扰。

3. **符合标准**：我们将自身限制在常规的 TCP/UDP/ICMP 连接尝试，并遵循符合 RFC 的协议。我们从不试图利用任何漏洞，确保我们的扫描是非侵入性和合乎伦理的。

4. **负责任的披露**：最后，出于隐私考虑，我们避免发布发现的外围地址。我们还会向相关的设备供应商和网络管理员披露所有发现的弱点或漏洞，帮助提高互联网的整体安全性。

## 行动号召

我们鼓励所有 XMap 用户在进行网络扫描时遵循这些最佳实践。这样做可以帮助确保您的扫描活动是合乎伦理、负责任且干扰最小的。通过共同努力，我们可以在推进网络测量研究领域的同时，为一个更安全、更有保障的互联网做出贡献。

有关如何负责任地进行网络扫描的更多信息，您可以参考 [ZMap 扫描最佳实践](https://github.com/zmap/zmap/wiki/Scanning-Best-Practices)。

## 并行运行？

我们不建议同时运行多个可能对网络造成显著压力的命令，因为每个人的资源都是有限的。根据我们的实践经验，在某大学的一台服务器上同时运行三个或更多类似如下的命令，极有可能导致命令异常终止（由于内存不足等原因），从而可能导致结果不完整：

```shell
sudo xmap -6 -B 15M -M icmp_echo_gw --iid-module=rand -o result/test.txt -O json --output-fields="saddr,outersaddr,type,code" --output-filter="(success = 1 || success = 0) && (repeat = 0 || repeat = 1)" -x 64 xxxx:xxxx::/32
```

我们建议将数据包速率（`-R` 或 `-B`）设置为您的网络能够处理的最大值，并逐个运行命令。
